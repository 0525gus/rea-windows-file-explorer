# 최종 소스 접근 게이트 — 승인용 변경안

근거: requirements §2.2는 역공학과 사후 검증의 디렉터리 및 접근 권한 분리를 요구하고, §14.6은 시스템 변경/위험한 파일 작업의 사전 승인을 요구한다. 아직 아래 ACL 변경은 실행하지 않았다.

현재 verification/는 비어 있고 verification/source/는 존재하지 않는다. Explorer++ 소스는 다운로드·열람하지 않았다.

## 정확한 변경 범위

1. **새 빈 디렉터리** `C:\dev\Windows_fileexplore\verification\source`만 생성한다. 기존 경로가 생겼으면 소유 상태와 내용 부재를 재검사하고 예상 밖 자료가 있으면 중단한다.
2. 현재 NTFS DACL/owner/SID와 보안 설명자를 `docs/analysis/source-gate-acl-backup.json`에 먼저 저장한다. 상위/다른 디렉터리 권한은 변경하지 않는다.
3. 알려진 비소스 probe 텍스트 하나를 생성하고 현재 사용자 SID에 이 디렉터리와 하위 파일의 **ReadData/ListDirectory** 읽기 거부 규칙을 추가한다. 기존 규칙은 보존한다. 계정 생성·관리자 권한 부여·시스템 보안 설정 변경은 하지 않는다.
4. 동일 사용자 토큰의 디렉터리 열거와 probe 읽기가 실제 접근 거부가 되는지 확인하고 결과를 기록한다. 경로 이름만 나눈 것을 권한 분리로 세지 않는다. 소유자는 ACL 복구 능력이 있으므로 악의적인 owner/관리자를 차단하는 보안 격리라고 주장하지 않는다.
5. 초기 구현·A/B 산출물·분석 보고서를 고정하고 파일별 SHA-256 freeze manifest와 Git 상태를 보존한 **Phase 6에만** 백업 ACL을 이 경로에 복원한다. freeze manifest의 파일들이 여전히 일치하는지 검증한 뒤 원본 소스를 이 사후 검증 디렉터리로만 확보한다. 초기 구현에 원본 소스 내용을 반영하지 않는다.

승인 대상은 위 새 검증 디렉터리의 읽기 잠금 및 최종 freeze 검증 후 원래 ACL 복원까지다. 변경 실패 시 기존 백업과 소유 경로를 유지하며, 다른 경로를 재귀 삭제하거나 사용자 데이터 권한을 바꾸지 않는다. 승인 전에는 현재처럼 원본 소스 부재/비열람을 유지하며 설계·재구현을 진행할 수 있다.
