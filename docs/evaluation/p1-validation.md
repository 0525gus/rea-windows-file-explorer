Started **2026-10-22, Asia/Seoul**. This ledger covers Phase 5 against the full [requirements](../requirements.md). The initial-final archived **09:01 Windows run passed 5/5 suites: 70 QtTest cases passed, 4 skipped, 0 failed**; the latest Linux native-ext4 run passed **5/5: 69 passed, 5 skipped, 0 failed**. Each total includes 10 init/cleanup cases. The new real breadcrumb click/history/Ctrl+L/error-preservation test passes on both platforms, with separate native breadcrumb observation. Displayed-deletion recovery, folder-rename failure/recovery and production-operation close/fresh-window cases also pass. Native cross-application drag remains unverified. [UI design review](ui-design-review.md) and the [initial report](initial-report.md) summarize the pre-source-validation implementation and its limits. Earlier runs below remain historical; the [P0 gate](../architecture/phase4-validation.md) is unchanged.

Only new `QTemporaryDir` children are mutated. By default their parent is project `test-data`; `REA_OPERATION_TEST_ROOT` may select an existing absolute parent, for example native Linux `/tmp`. An invalid override fails suite initialization. The override never authorizes removal of its parent. Test source files and competing destination files are created exclusively by the test. Original Explorer++ source, experiment-A implementation/context, the locked source gate, and immutable shared fixtures are not read or modified for P1 operations. No new REA call or desktop automation is involved. Tests call the production `makePlatform()` adapter; the controlled session adapter establishes application lifecycle semantics only.
