# Phase 5 contract extension

Independent implementation remains inside arm A and uses no REA, B design/code, or original source. P0 is preserved under artifacts/p0-freeze with its manifest.

The platform contract now accepts typed OperationRequest (Copy, Move, Trash, Remove, Rename, NewFolder, Cleanup), explicit collision policy and destructive confirmation. Results preserve per-item success, skip, error, recovery paths and separately owned cleanup paths. The application OperationManager owns one mutation worker, cancellation token, throttled progress and the session's retained cleanup list. Buttons, view input, clipboard and incoming local-file URL drops submit the same request path. GUI never performs filesystem mutation directly.

Filesystem preflight resolves existing identities, rejects same/overlapping source and destination, validates leaf names, rejects unknown link/reparse mutation and directory merging, checks all initial collisions before mutation, and counts source bytes without following links. Regular-file replacement copies into an exclusively created sibling workspace before preserving the prior destination and committing. Failed cleanup retains the workspace record, held native directory handle and explicit recovery path. Retry refuses a replaced identity and remains available after a transient sharing failure in the same process. Recovery authority is never reconstructed from a display path alone. Retained cleanup is session-scoped; process restart requires manual recovery from the reported path rather than inferred ownership.

Windows no-replace rename uses MoveFileExW without replacement flags. Linux first attempts renameat2(RENAME_NOREPLACE); WSL DrvFS rejected the flag during actual tests, so the unsupported-filesystem case uses Qt's documented destination-preserving QFile/QDir rename contract. There is no claim of adversarial concurrent-path atomicity under that fallback. Cross-volume source removal follows successful copy and a second source check. Actual cross-volume move has not yet been exercised because the owned fixture/workspace is on one volume.

The shared item model produces local file URL MIME and one selection model spans Details/List/Icons. Selection facts are collected once from selected name-column indexes, so icon/list selection is not mistaken for absent full-table row selection. A single FileViewInput owns both view keyboard commands and drag/drop acceptance; text edits retain their own copy/paste behavior. Remote URLs and link-drop actions are rejected. Native desktop cross-application drag gestures remain a distinct verification item from offscreen URL/drop-event integration tests.

Shutdown cancels and waits for owned mutation/list workers. Cancellation before commit cleans only owned staging data; cancellation during final cleanup finishes cleanup of an already committed copy. Mixed item failures are retained alongside successful items. The UI does not advertise general operation cancellation/undo as a completed P2 feature.
